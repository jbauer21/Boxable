# Boxable on Render Free

Use the existing Boxable project and one **Web Service**, connected to
`jbauer21/Boxable`, branch `main`, language **Docker**, plan **Free**.
Leave root directory and Docker command empty. Dockerfile: `./Dockerfile`.
Health check: `/api/health`. Enable automatic deployment on commit.
No paid database, disk, custom domain, or subscription is needed.

The multi-stage image builds React with Node 24 and runs FastAPI with Python 3.11.
`/` serves the built app; `/api/*` is mounted directly onto the existing API.
Static assets and the Google callback use the same origin. Runtime `PORT` comes
from Render. Access logs are disabled to avoid logging OAuth callback codes.
Only public Supabase values are passed to the frontend build.

callback from it. `PUBLIC_APP_URL` is an optional HTTPS origin override, without
a path or trailing slash. Keep it unset on Render unless explicitly needed.
Redeploy after changing frontend values. Missing Google/SMTP credentials do not
prevent guest planning, measurement or exports from starting.

## Google OAuth setup

Use `boxableorganization@gmail.com` in Google Cloud. Create a project and configure
Google Auth Platform with app name **Boxable**, that support/contact email, and an
external audience. In testing, add the accounts that will sign in as test users.
Create an OAuth client of type **Web application**.

Once Render assigns `https://YOUR-SERVICE.onrender.com`, enter:

- Authorized JavaScript origin: `https://YOUR-SERVICE.onrender.com`
- Authorized redirect URI: `https://YOUR-SERVICE.onrender.com/auth/google/callback`
- For the existing local Supabase OAuth flow, also allow
  `https://dlnyuqnwmojzleejussf.supabase.co/auth/v1/callback`.

Use only `openid`, `email`, and `profile`. Paste the ID and secret into Render's
`GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. Also enable Google in Supabase Auth
and configure the same client ID and secret there. Do not disable nonce checking.
Supabase validates Google's identity token and remains the sole account authority,
including verified identity linking and owner-only database/storage access.

Production uses tab-bound state, PKCE and a hashed nonce. The backend exchanges
the Google code using its secret and the fixed Render callback. The frontend
hands the ID token plus original nonce to Supabase, which verifies it before
creating a session. Tokens are not placed in URLs. A failed/cancelled/expired flow
returns to sign-in and preserves drafts. Existing local development continues
using Supabase's hosted OAuth redirect. The Docker build selects the production flow.

In Supabase → Auth → URL Configuration, set Site URL to the Render origin with
`/` and add that exact URL to the redirect allow-list. Preserve existing local
callbacks. Keep email verification and the 15-character password minimum enabled.
The database migration in [ACCOUNTS.md](ACCOUNTS.md) remains necessary for saved drawers.

## Brevo transactional email

Sign up for Brevo Free with `boxableorganization@gmail.com`; complete onboarding
and sender verification. No domain purchase is required for app hosting. Brevo
may impose sender/deliverability restrictions on free-mail addresses; do not
claim delivery ready until a message arrives in a real inbox.

Render Free blocks SMTP ports 25, 465 and 587. Brevo supports 2525. The server uses
STARTTLS with certificate verification on 2525 and fails closed if TLS is unavailable.
No anonymous email-sending endpoint is exposed. Server code can call
`mailer.send_transactional_email(recipient, subject, text)` for transactional events.
With the environment loaded, run `cd backend && python -m mailer YOUR_TEST_EMAIL`
to send a delivery check. Credentials are read only from the environment.

Account confirmation/recovery emails are generated by **Supabase Auth**, not the
Render process. Configure the same Brevo SMTP credentials and verified sender in
Supabase → Auth → SMTP, using 587 or 2525. Apply `supabase/templates/confirmation.html`
and `supabase/templates/recovery.html`. Render environment variables alone cannot
configure a hosted Supabase project's SMTP provider. Never disable verification
as a workaround for missing delivery. Verify registration and recovery in a real inbox.

## Local production check

Build with `cd frontend && npm ci && npm run build`. From `backend`, install
`requirements.txt` and run `uvicorn web:app --host 127.0.0.1 --port 10000 --no-access-log`.
Open `http://127.0.0.1:10000/`; check `/api/health`, photo measurement and a small 3MF.
For the actual production image, run `docker build` with the two public Supabase
build arguments and run the image on port 10000. Never pass secret build arguments.

Render Free sleeps when idle, so first requests can be slow. Its 512 MB memory
limit may constrain large CAD generations. Verify a representative small export
after deployment; do not silently change the plan to paid if a workload exceeds it.
